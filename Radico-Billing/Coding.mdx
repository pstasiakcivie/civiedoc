# **Accessing Coding Module**

The **Coding Module** can be accessed directly from the **left-side menu**. Once selected, the module opens to the **Coding Dashboard**, which provides a consolidated view of coding activities, productivity, and worklists.

## **Coding Dashboard**

The **Coding** \*\*Dashboard \*\*provides users with a centralized view of their coding activities, allowing them to track daily performance, view worklists, and access reports based on status. This helps prioritize tasks and ensures efficient workflow management. The **Coding Dashboard** gives a quick summary of your coding activity and worklists:

**Your Daily Progress**: Shows how many records you’ve completed today and the total RVUs.

**Coding Bucket**: A pie chart showing report counts Pending, Submitted, CAP, and Disabled.

**Daily Client Activity**: Displays the number of new and completed reports by client.

## **Quick Access Menu**

Located within the dashboard, the **Quick Access** menu allows users to easily filter and open coding records based on their status:

**New:** Displays newly assigned records available for coding.

**All:** Lists all records accessible to the user.

**In Progress:** Shows records that have been opened and are currently being worked on but not yet finalized.

## **Worklists**

In addition to the dashboard view, coders can organize and manage records through dedicated worklists:

- **My Private Worklist:** A personalized list where users can maintain their own set of records for individual tracking and workflow management.
- **Shared Worklist:** A collaborative list where multiple users can access and work on records, enabling team-based coding and shared accountability.

# **Managing Coding Records**

The system provides several actions for managing a coding record. The availability of these actions may vary depending on the user’s role and workflow permissions.

- **Accept:** Acknowledge any warnings or errors, and proceed with editing CCE (Clinical Coding Edit) errors if applicable.
- **Approve:** Finalize the coding record after review. This action updates the record status from _In Progress_ to _Approved_ and makes it ready for claim submission.
- **Undo and Send Back to Coding:** Reverses an approved record and returns it to the coding queue for correction or rework.
- **Disable:** Temporarily inactivates a coding record, preventing further actions until it is re-enabled.
- **Save:** Retains any modifications made to the coding record without finalizing them, allowing the user to continue work at a later time.
- **Mark as CAP:** Flags the coding record under **Coding Assistance Plan (CAP)** to highlight issues or clarifications required before approval.

## **Marking a Record for Coding Assistance (CAP)**

Use the CAP feature when physician input or clarification is needed for a coding report.

<Steps>
  <Step title="To mark a record as CAP">
    Click the **CAP** button at the top right corner of the right panel.

    ![9 Pn](/images/9.png)
  </Step>
  <Step title="Select a CAP Reason from the dropdown.">
    Upon selecting a relevant **CAP** **Reason**, add **Comment(s)** (optional) for context or clarification.

    ![10 Pn](/images/10.png)
  </Step>
  <Step title="Submit or Cancel">
    Click the **Submit** button to mark the record as a **Coding Assistance Portal (CAP)** request.

    Click the **Cancel** button to discard any changes and exit without submitting.
  </Step>
</Steps>

<Note>
  **Note**

  - When a record is marked as CAP, it is removed from the active coding queue, and its coding status updates to CAP. This change is also reflected in the Activity tab.
  - The report is automatically routed to the CAP portal for physician review. If the physician responds via the Discussion Panel in the CAP portal, the message appears in the Discussion tab of the Coding module for the coder or manager to review.
  - If the physician takes any of the following actions in the CAP portal—Addendum in the Hospital System, No Change, Sign Change, or Sign Anyway—the CAP status is updated to Addendum, and the corresponding status in the Coding module changes to In Progress. It is also reflected in the Activity tab.
  - If the CAP record expires without physician action, its status in the CAP portal becomes Expired, and the Coding module updates the record’s status back to In Progress.
  - If a coder manager flags a record as CAP and the physician reassigns it to a coder who then raises a question via the CAP Discussion Panel, the Days to Expire status changes to In Coder’s Queue. If the coder manager or admin reverts the record, the expiration timer resets to the Default days to expire in the CAP portal.
</Note>
